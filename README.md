# Аудит датасета Wine Quality (White Wine)

Первичный аудит данных, проверка качества, анализ распределений и подготовка выводов для ML.

---

## О датасете

**Wine Quality (White Wine)** — классический датасет из репозитория UCI Machine Learning. Содержит физико-химические характеристики белых вин (португальские «Vinho Verde») и экспертную оценку их качества по 10-балльной шкале.

**Структура:**
- 4898 наблюдений (бутылок вина)
- 11 входных признаков + 1 целевая переменная (`quality`)
- Все признаки числовые (`float64` / `int64`)

**Признаки:**

| Признак | Описание |
|---------|----------|
| `fixed acidity` | Фиксированная кислотность (г/л) |
| `volatile acidity` | Летучая кислотность (уксусная кислота) |
| `citric acid` | Лимонная кислота |
| `residual sugar` | Остаточный сахар |
| `chlorides` | Хлориды (соль) |
| `free sulfur dioxide` | Свободный SO₂ |
| `total sulfur dioxide` | Общий SO₂ |
| `density` | Плотность |
| `pH` | Кислотность среды |
| `sulphates` | Сульфаты |
| `alcohol` | Содержание алкоголя, % |
| `quality` | **Целевая переменная** — оценка качества (3–9) |

---

## Ход аудита

### 1. Общая статистика

Датасет загружается без ошибок. Все 12 столбцов на месте, типы данных корректные: 11 признаков с плавающей точкой (`float64`) и 1 целочисленный (`quality`). Признаки имеют разный масштаб: от `chlorides` (сотые доли) до `total sulfur dioxide` (десятки и сотни). Это важно — без масштабирования алгоритмы на основе расстояний (KNN, SVM, K-means) будут работать некорректно.

### 2. Пропуски

**Пропусков не обнаружено.** Все 4898 строк × 12 столбцов заполнены. Это значит:
- дополнительные процедуры импутации (заполнения медианой/модой) **не требуются**;
- все наблюдения можно использовать для анализа и обучения моделей без риска смещения.

### 3. Дубликаты

**Обнаружено ≈ 937 дубликатов (~19% от исходного объёма).** Это критичная находка:
- в датасете много **полностью идентичных строк** — одни и те же вина повторяются;
- если оставить их и разбить данные случайно на train/test, **одна и та же строка может попасть и в обучение, и в тест** → это утечка данных и завышенные метрики;
- **дубликаты удалены**, итоговый размер — **3961 наблюдение**.

### 4. Константные признаки

**Константных признаков нет.** У каждого признака — десятки или сотни уникальных значений. Это хорошо: ни один из столбцов не несёт нулевой информации и не подлежит удалению.

### 5. Баланс классов (целевая переменная `quality`)

Распределение оценок сильно **несбалансировано**:

| Оценка | Количество | Доля |
|--------|-----------|------|
| 3 | 20 | 0.5% |
| 4 | 153 | 3.9% |
| 5 | 1175 | 29.7% |
| 6 | 1788 | 45.1% |
| 7 | 689 | 17.4% |
| 8 | 131 | 3.3% |
| 9 | 5 | 0.13% |

- **Классы 5 и 6 вместе — ~75%** всех наблюдений.
- **Класс 9 содержит всего 5 примеров**, класс 3 — 20 примеров.
- **Коэффициент дисбаланса max/min ≈ 358** — экстремальный.

**Последствия:**
- Модель, которая всегда предсказывает `quality = 6`, уже даёт точность ~45%. Это ловушка для оценки качества моделей через accuracy.
- Для обучения нужны **стратифицированное разбиение** (train/test), **веса классов** (`class_weight`), **ресемплинг** (SMOTE, undersampling) или **регрессионный подход** вместо классификации.
- Метрики: **macro-F1, balanced accuracy, ROC-AUC (OvR)**, а не accuracy.

### 6. Распределения числовых признаков

Построены гистограммы всех 11 признаков. Ключевые наблюдения:

- **`alcohol`, `pH`, `density`** — распределения близки к нормальным (асимметрия в пределах ±0.5).
- **`residual sugar`, `chlorides`, `sulphates`, `total sulfur dioxide`** — сильно **правосторонняя асимметрия** с длинным хвостом (skew > 1). Есть вина с экстремально высокими значениями (например, остаточный сахар > 60 г/л).
- **`citric acid`** — много значений близко к нулю.
- **`free sulfur dioxide`** и **`total sulfur dioxide`** — скошены вправо, что физиологически логично: большинство вин имеет нормальный уровень, но есть отдельные партии с высокой сульфитацией.

**Рекомендации по трансформации:**
- Для асимметричных признаков — **логарифмирование** (`np.log1p`) или **Box-Cox / Yeo-Johnson**.
- Для ML-моделей на расстояниях — **RobustScaler** (устойчив к выбросам) вместо StandardScaler.

### 7. Boxplot и анализ выбросов (приоритетные признаки)

Для 6 ключевых признаков построены ящики с усами по методу IQR (Q1 − 1.5·IQR, Q3 + 1.5·IQR):

| Признак | Доля выбросов | Комментарий |
|---------|---------------|-------------|
| `residual sugar` | ~7% | Много «сладких» вин — реальные данные, не ошибки |
| `chlorides` | ~5% | Несколько солёных образцов |
| `total sulfur dioxide` | ~3% | Партии с высокой сульфитацией |
| `volatile acidity` | ~2% | Несколько «уксусных» вин |
| `alcohol`, `pH`, `density` | <1% | Хвосты, но в норме |

**Важное замечание:** выбросы в этом датасете **не являются ошибками измерений** — это реальные физико-химические свойства отдельных вин. Их удаление может привести к потере информации о редких, но настоящих сортах. Правильный подход:
- **не удалять**, а использовать устойчивые модели (Random Forest, Gradient Boosting) или RobustScaler;
- либо применять **винзоризацию** (клиппинг) при линейных моделях.

### 8. Корреляционный анализ

Построена тепловая карта корреляций Пирсона. Связь признаков с целевой переменной `quality`:

| Признак | Корреляция с quality | Интерпретация |
|---------|---------------------|---------------|
| `alcohol` | **+0.44** | Чем крепче вино, тем выше оценка |
| `density` | **−0.31** | Плотнее → ниже качество (обратно к алкоголю) |
| `volatile acidity` | **−0.19** | Уксусный привкус снижает оценку |
| `chlorides` | **−0.21** | Соль вредит вкусу |
| `residual sugar` | **+0.10** | Слабая положительная связь |
| `pH` | +0.10 | Слабо |
| `sulphates` | +0.05 | Почти нет связи |

**Мультиколлинеарность:**
- `alcohol` ↔ `density` — сильная обратная связь (−0.78). Логично: спирт легче воды, поэтому крепкое вино менее плотное.
- `free sulfur dioxide` ↔ `total sulfur dioxide` — прямая связь (0.62).
- `fixed acidity` ↔ `pH` — обратная (−0.43).

Для линейных моделей рекомендуется **удалить `density` или `alcohol`** (или использовать Ridge/Lasso для регуляризации).

## Итоговые выводы

### Что хорошо
1. **Датасет полный** — нет пропусков.
2. **Признаки информативны** — нет констант, все вариативны.
3. **Связи с целевой переменной** физически осмысленны: алкоголь, летучая кислотность, плотность — главные драйверы качества.

### Что требует внимания
1. **Экстремальный дисбаланс классов** (max/min ≈ 358) — без обработки модели будут «тупыми» и всегда предсказывать `6`.
2. **~19% дубликатов** — обязательно удалять, чтобы не было утечки.
3. **Сильная асимметрия** у `residual sugar`, `chlorides`, `sulphates` — нужна трансформация.
4. **Выбросы реальны**, а не ошибочны — удалять их не стоит.
5. **Мультиколлинеарность** между `alcohol` и `density`, `free` и `total sulfur dioxide`.

### Рекомендации по подготовке данных для ML

1. **Удалить дубликаты** — обязательно (уже сделано).
2. **Разбить данные стратифицированно** по `quality` — иначе train/test не будут репрезентативны.
3. **Масштабировать** признаки (StandardScaler / RobustScaler).
4. **Трансформировать** асимметричные признаки (`residual sugar`, `chlorides`, `sulphates`) логарифмом или Box-Cox.
5. **Работать с дисбалансом:** `class_weight='balanced'`, SMOTE или объединение редких классов (3, 9 → 4; 8 → 7).
6. **Рассмотреть регрессию** вместо классификации: предсказывать `quality` как число, а затем округлять — это убирает проблему дисбаланса.
7. **Метрики:** macro-F1, weighted-F1, MAE/RMSE (если регрессия), confusion matrix. **Accuracy не использовать.**
8. **Топ-признаки для старта:** `alcohol`, `volatile acidity`, `density`, `chlorides`, `residual sugar`.

### Что даёт аудит

Аудит показал, что датасет **пригоден для моделирования**, но требует **аккуратной предобработки**: чистка дубликатов, работа с дисбалансом, трансформация скошенных признаков. Без этих шагов любая модель покажет обманчиво высокую accuracy при полной бесполезности для реального предсказания качества вина.
